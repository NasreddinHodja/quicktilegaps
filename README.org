#+title: Quick Tile Gaps

A KWin script that puts gaps around windows placed by Plasma's ordinary quick tiling (=Meta= + arrow keys, dragging a window to a screen edge) and around maximized windows.

[[file:screenshots/smallgaps.png]]

Maximized windows get their own gap, which can be turned off on its own.

[[file:screenshots/maximized.png]]

* Intent

KWin has built-in gaps, set with the Padding option in the tile editor, but they only apply to custom tile layouts. Windows placed with quick tiling, the default, get no gaps.

KWin builds the =QuickRootTile= and each of its eight children with padding hardcoded to zero (=src/tiles/quicktile.cpp=), and the tile editor's padding setting is only applied to the custom layout's root tile (=src/tiles/tilemanager.cpp=). This is the case in every Plasma 6 release up to 6.8 and on =master=. As of September 2026 there is no open merge request changing it.

This script adds gaps to quick-tiled and maximized windows, and leaves windows in custom layouts alone so their native padding keeps working.

* Configuration

System Settings → Window Management → KWin Scripts → Quick Tile Gaps → configure button.

| Setting                  | Default | What it covers                                                   |
|--------------------------+---------+------------------------------------------------------------------|
| Between tiled windows    |    8 px | Total space between two tiled windows sitting next to each other |
| Around tiled windows     |    8 px | Space between a tiled window and the work area edge              |
| Around maximized windows |    8 px | Space on all four sides of a maximized window, 0 to disable      |

Inner and outer are separate because they are visually different distances. A single value makes the channel between two windows read heavier than the margin at the screen edge, or the other way around, depending on which one you tune for.

#+begin_example
+------------------------------------------------+
|    .----------------.    .----------------.    |
|    |    window A    |    |    window B    |    |
|    '----------------'    '----------------'    |
+------------------------------------------------+
 <-->                  <-->
 outer                 inner
#+end_example

"Between tiled windows" is the *total* gap, so each window gives up half of it on a shared edge. Set it equal to your tile editor padding to make quick tiling and custom layouts look identical; the tile editor uses the same half-on-shared-edges rule.

Settings are stored in =~/.config/kwinrc= under =[Script-quicktilegaps]=, as =InnerGap=, =OuterGap= and =MaximizedGap=, if you would rather keep them in your dotfiles.

* Install

Available on the [[https://store.kde.org/p/2371140][KDE Store]].

Or, from inside the script directory:

#+begin_src sh
kpackagetool6 --type KWin/Script --install .
#+end_src

Then enable it in System Settings → Window Management → KWin Scripts.

To update an install you already made:

#+begin_src sh
kpackagetool6 --type KWin/Script --upgrade .
#+end_src

* Requirements

+ Plasma 6.3 or later. =Window.maximizeMode= only became scriptable in 6.3; on 6.0 to 6.2 gaps for tiled windows would work but maximized windows would not be touched.

Only tested on Wayland.

* How it works

Every managed window is watched for =tileChanged=, =maximizedChanged= and =frameGeometryChanged=. When one of those fires, the script asks KWin where the window *should* be, which is =tile.absoluteGeometry= for a tiled window or the maximize area for a maximized one, insets that rect, and writes it back.

Two details do most of the work:

+ A window is only gapped when its frame still matches that rect exactly. Once inset it no longer matches, which is what keeps =frameGeometryChanged= from feeding back into itself, and it is also why a window you have resized by hand is left alone.
+ Tile geometry is derived from the same =clientArea(MaximizeArea)= rect the script compares against, so whether a tile edge lies on the work area boundary is an exact comparison. Any other edge is treated as shared with a neighbour and gets half the inner gap.

Quick tiles are told apart from custom ones by walking up to the topmost tile and comparing it against the tile editor's root for that output and desktop. Anything that is not that root belongs to the =QuickRootTile=, which scripts cannot reach by any other route.

* Differences from similar scripts

+ [[https://github.com/nclarius/tile-gaps][nclarius/tile-gaps]] ("Window Gaps") calls =workspace.clientList()= and =clientAdded=, which were removed in KWin 6, so it does not run on Plasma 6. Its [[https://github.com/nclarius/tile-gaps/issues/23][port issue]] has been open since March 2024.
+ [[https://github.com/FredworkLemmas/kwin-tile-gaps][Interstitia]] is a fork of nclarius/tile-gaps ported to the Plasma 6 API. Compared to this script:
  + It changes any normal, resizable window near a screen edge, another window, or a half or quarter line of the screen. This script only changes quick-tiled and maximized windows.
  + It works out the layout from window positions, matched within a pixel tolerance. This script reads the tile KWin assigned to the window (=window.tile=).
  + It does not tell windows in custom tile layouts apart from other windows. This script leaves them to KWin's own padding.
  + With its maximized option on, it un-maximizes windows before resizing them. This script resizes them and they stay maximized.
  + It has more settings: a gap per screen edge, floating panel adjustment, and an application include/exclude list.
+ [[https://github.com/peterfajdiga/karousel][Karousel]] has its own gap settings, but it is a tiling script that changes how windows are arranged. This script leaves tiling itself to KWin.
